This walkthrough mirrors [`examples/minimal-node`](https://github.com/Joaoha/Bonsai/tree/main/examples/minimal-node) — a headless demo that asserts every step, so it doubles as a CI smoke test. You should be able to paste, run, and see a streamed response, a branch, a merge summary, and a wiki page in one sitting.

## What you'll build

By the end you will have run this loop end-to-end:

```
create project → chat on main → branch → chat in branch
  → merge (with editable summary) → distill → retrieve → audit trace
```

Every step is inspectable: `assembleContext()` gives you the exact `ContextPacket` a chat call will send before you spend a token; merge invokes an `editSummary` hook you control; distill writes a Markdown wiki page with frontmatter you can grep.

## Prerequisites

- Node.js `>= 20.11`
- A reachable Postgres URL (any modern Postgres). If you don't have one, the `examples/minimal-node` demo will spin one up via testcontainers when Docker is running.
- Optional: `OPENAI_API_KEY` if you want to swap in the real provider. The demo defaults to a deterministic in-process `FakeProvider`.

## 1. Install

<Steps>

1. Add the packages you need:

   ```bash
   npm i @bonsai/core @bonsai/storage-postgres @bonsai/provider-openai @bonsai/wiki-fs
   ```

2. Set your environment:

   ```bash
   export DATABASE_URL="postgres://user:pass@localhost:5432/bonsai"
   export OPENAI_API_KEY="sk-..."
   ```

</Steps>

## 2. Wire the adapters

`@bonsai/core` is a pure domain layer. You bring storage, a model provider, a wiki store, and a retriever. The Postgres adapter also ships an FTS retriever you can reuse.

```ts title="src/bonsai.ts"
import { Bonsai } from '@bonsai/core';
import {
  applyMigrations,
  createPostgresStorage,
  PostgresFtsRetriever,
} from '@bonsai/storage-postgres';
import { OpenAIProvider } from '@bonsai/provider-openai';
import { FsWikiStore } from '@bonsai/wiki-fs';
import { Pool } from 'pg';

const pool = new Pool({ connectionString: process.env.DATABASE_URL });
// migrationsRoot points at packages/storage-postgres/migrations in this repo;
// when you depend on the published package, copy those SQL files into your
// own migrations pipeline and point this at your copy instead.
await applyMigrations(pool, './migrations');

const storage = createPostgresStorage({ pool });

export const bonsai = new Bonsai({
  storage,
  provider: new OpenAIProvider({ apiKey: process.env.OPENAI_API_KEY! }),
  wiki: new FsWikiStore({ root: './wiki' }),
});

// The retriever is bound to a project, so you construct one per project
// once you have a project id (see step 3).
export function retrieverFor(projectId: string) {
  return new PostgresFtsRetriever({ pool, projectId });
}
```

<Aside type="note" title="Deterministic tests">
For CI and local dev, swap `OpenAIProvider` for a fake that returns fixed strings. The `examples/minimal-node` demo ships one you can copy.
</Aside>

## 3. Chat on main, then branch

```ts
const project = await bonsai.createProject({ name: 'demo' });
// createProject seeds exactly one branch, named "main".
const [main] = await storage.branches.findByProjectId(project.id);

// Want to see the exact context before spending a token? Call
// `bonsai.assembleContext(main.id)` — it returns the same ContextPacket
// that `chat()` sends to the provider.

// `chat()` is an async generator: it persists the user message, streams
// the reply, and persists the assistant message as it completes.
for await (const chunk of bonsai.chat(main.id, 'Give me three ideas for a weekend project.')) {
  process.stdout.write(chunk.content);
}

// Fork main at its last message into a branch to explore idea #3 in depth.
const mainMessages = await storage.messages.findByBranchId(main.id);
const forkPoint = mainMessages[mainMessages.length - 1]!.id;
const branch = await bonsai.createBranch({
  fromBranchId: main.id,
  forkPoint,
  name: 'weekend-3',
});

// Sibling branches do not leak into each other's context. This is enforced
// by ContextPacket assembly, not by hope.
for await (const chunk of bonsai.chat(branch.id, 'Sketch a two-day plan for idea #3.')) {
  process.stdout.write(chunk.content);
}
```

## 4. Merge back with a reviewed summary

Merge is a distinct user action, not a side effect. You get to edit the summary before it lands on the target branch.

```ts
const { merge, appliedMessage } = await bonsai.merge({
  sourceBranchId: branch.id,
  targetBranchId: main.id,
  editSummary: (draft) => `${draft}\n\nHuman note: keep the tent option, drop the raft.`,
});

console.log(merge.status); // 'applied'
console.log(merge.summary); // includes your human note
console.log(appliedMessage.isMergeCommit); // true — landed on `main` as a message
```

`editSummary` receives the provider-generated draft summary and returns the final text (sync or async) — it is called exactly once per merge, before the merge commit is written.

## 5. Distill into the wiki, then retrieve

Distill turns the merge (and its underlying transcript) into a durable Markdown page under `wiki/pages/` with a frontmatter block linking back to the merge and source messages. Retrieval picks it up on the next chat.

```ts
const distillation = await bonsai.distill({ mergeId: merge.id });
console.log(distillation.wikiPageSlug);  // e.g. "merge-weekend-3"
console.log(distillation.wikiPageTitle); // "Merge: weekend-3"
// The Markdown file itself lives at `<wiki root>/pages/<slug>.md` with a
// frontmatter block carrying `mergeId` and `sources[]` back to the raw
// transcript — see the Wiki concept page.

// Retrieval goes through the Retriever you constructed for this project,
// not through the Bonsai façade — Bonsai has no `retrieve()` method.
const retriever = retrieverFor(project.id);
const hits = await retriever.search('weekend tent plan');
console.log(hits[0].title); // same page
```

## 6. Audit trace

Every wiki page traces back to its merge, and every merge back to its raw transcript. That contract is why distill and merge stay separate user actions.

```ts
const trace = await bonsai.resolveTrace(distillation.wikiPageSlug);
console.log(trace?.wikiSlug, trace?.wikiTitle);
```

<Aside type="caution" title="Trace resolution is minimal today">
The `Bonsai` façade's `resolveTrace` currently only confirms the wiki page exists and returns `{ wikiSlug, wikiTitle, transcript: [] }` — it does not yet join back to `merge` or `branch`. The frontmatter written by `distill()` (`mergeId`, `sources[]`) already carries that link; a fuller `AuditTraceResolver` that reads it back is on the roadmap. See [`resolveTrace`](/api/core/functions/resolvetrace/) and [`AuditTrace`](/api/core/interfaces/audittrace/) for the full shape.
</Aside>
